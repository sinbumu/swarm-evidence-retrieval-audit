# Matched topology protocol description

**Public snapshot adaptation.** This describes the historical study; it is not a new preregistration or an execution instruction. Private Git ancestry, original locks and raw evidence are absent. Source commit/file hashes in [provenance](../provenance.json) identify the supplied bytes but do not independently establish when the design was fixed. See [evidence limits](evidence-availability.md). Operational coordination text is omitted; the original remains preserved privately.

## 1. Question, estimand and expected nulls

At the same number of distinct required records, same candidate pool and payload-read budget, does replacing a chain with a two-branch AND fork/join change **complete recovery of the private true evidence set** by one general pointer-frontier procedure? Analyze each fixed `k × budget × observation condition` separately. The intervention changes edges, branching, path length, number of edges and the location of redundancy; these structural properties are not separately identified.

This is a synthetic structure/access study. It is not a correlated-failure experiment, a new trustworthy checker, an identification benchmark, a strategic-agent model, or evidence of deployment safety. Equal recovery in intact sufficient-budget cells is an expected contract consequence, not a novel empirical success. At `k=8, B=4`, completeness must be zero for every budget-limited method. The blind baseline's topology difference must be exactly zero because its input and required set are paired. Round counts, recall and disrupted-reference cells can differ even when complete-recovery differences are zero. Retain nulls and negative findings; do not manufacture an overall advantage by weighting conditions after observing results.

## 2. Private truth and matched cardinality

`k ∈ {4,8}` counts **all distinct records in the true required set**, including the root, final anchor/join, both branches and any shared ancestor exactly once. Budgets `B ∈ {4,8,12}` count distinct successfully read payload records, including the anchor. Every view has **N=32 candidate records**, all readable; exactly `N−k` are distractors. N does not change across topology, k, budget, fault or label. There is no hidden universe of extra candidate records.

Use latent slots `v0 … v(k−1)` only inside the private generator/audit data. The anchor is `v(k−1)`. Arrows below point from a record to its prerequisites, opposite the forward workflow direction.

| k | Chain prerequisite edges | AND fork/join prerequisite edges | Required / distractor / candidate records | True edges |
| --- | --- | --- | --- | --- |
| 4 | J→B→A→R | J→{A,B}; A→R; B→R | 4 / 28 / 32 in both | Chain 3; fork/join 4 |
| 8 | J→B3→B2→B1→A3→A2→A1→R | J→{A3,B3}; A3→A2→A1→R; B3→B2→B1→R | 8 / 24 / 32 in both | Chain 7; fork/join 8 |

In general, `m=(k−2)/2`: private slots are root `v0`, branch A `v1…vm`, branch B `v(m+1)…v(2m)`, and J `v(k−1)`. The chain uses the same slots in increasing workflow order. The fork/join shares exactly one root and has two disjoint length-m branch interiors. No additional fork record, approval record, join manifest or proof record is hidden outside k. Root and join each consume one ordinary payload read. The N−k distractors form disjoint four-record AND diamonds: for each consecutive private background block `(d0,d1,d2,d3)`, d1→d0, d2→d0 and d3→{d1,d2}. There are7 such blocks for k4 and6 for k8. They are never private ancestors of the target anchor. Thus arities0/1/2 also occur in irrelevant records and do not directly mark required membership. These background edges and payloads are identical across the target-topology pair. Total private pool edges are31 for chain and32 for fork/join; target-set edges remain k−1 and k.

For each family and k, share the **same 32 opaque record IDs, anchor, required membership, approval assignments, distractor IDs, catalog and wire sizes** across both topologies. Only prerequisite edges/arity differ. The private DAG contains every candidate node and its true predecessor list. Compute `R = {anchor} ∪ all private ancestors(anchor)` from that DAG before any observation mutation. Never reconstruct R from observed pointers, declared arity, checker output or selected records. A false reference cannot change R, private edges or the private label. The common required set has cardinality k in both structures, while their true edge counts differ and are charged/disclosed.

## 3. Labels, AND semantics and trust

Each family/k has two paired label views. In the **normal** view, every required record's private Boolean `approved` is true. In the **violation** view, exactly one uniformly chosen required nonanchor record has `approved=false`; all other required records, including the anchor, remain true. Each distractor independently has `approved=true` with probability0.5, sampled once per family/k and shared across both label views and all topologies/conditions/budgets. Distractor approvals never enter the private target label. Consequently, seeing a false approval in an arbitrary record does not itself reveal private membership or the target label. Choose the required negative node once using a private domain-separated random stream, independent of topology, observation mutation and IDs. Use the same choice in both topologies, every budget and condition. Never force the negative node onto the fault-cut branch. Private label is `normal` iff the Boolean AND over **all unique records in R** is true, otherwise `violation`. There is no OR branch or optional branch. Reaching one branch, or finding a single true approval, cannot establish a true normal label.

The payload contains an ID, an integer `declared_arity`, a parent-slot list, and a Boolean `approved`; no label field, private slot, role, workflow ID, depth, topology, k, or truth-membership marker. Arity 0 is an asserted terminal/root claim, 1 an asserted single dependency, 2 an asserted AND dependency. All declared dependencies must resolve for a definitive **observed-graph** diagnostic; shared ancestors are deduplicated by record ID, not treated as optional branches. Parsing or an ID match is not authentication.

**No edge, root/arity declaration, or approval is cryptographically authenticated.** There is no signature, trusted root certificate, trusted dependency count, hidden checker whitelist or private-truth lookup available to a method/checker. The limited mutation model preserves approvals and declared arity, but this is a simulator restriction, not a real trust guarantee. Even a fixed-size record returned under the requested ID could make false dependency assertions. No new trusted checker is introduced. Authentication attempts/bytes/cost are explicitly zero because authentication is absent.

## 4. Observations and frozen faults

The full catalog contains only opaque `id` and `payload_bytes=512`, one **128-byte padded canonical JSON record** per candidate; catalog order is ascending opaque ID. The **128-byte query** contains only `anchor_id` and B. All payloads are **512-byte padded canonical JSON**, with sorted keys, compact separators, ASCII content and trailing ASCII spaces. Two parent IDs fit; validate length before padding and reject overflow. There are no timestamps, public degree counts, object/resource hints, label flags, source indices or variable-length side channels in catalog/query. A method may learn asserted arity and parents only after paying to read that payload.

Private 32-byte randomization keys are sampled **once per split**, before generation; development and evaluation use different keys. Keep the keys in Git-excluded provenance/locks, never in selector/checker inputs. Use HMAC-SHA256 with disjoint UTF-8 namespace strings and canonical JSON arguments to derive private random streams and 128-bit opaque IDs. The exact stream input is ASCII compact canonical JSON of `["SWARM-018-topology-v1", split, family_seed, k, namespace, ...parts]`, where split is `dev` or `eval`. Namespace `id` has one integer pool-slot argument, 0–31; its digest's first16 bytes become lowercase hex. For the other namespaces, use the full HMAC digest as a big-endian integer seed for an isolated Python3.13.1 `random.Random`, then call `randrange` once: `violation_node` chooses slot0…k−2, `anchor_branch` chooses A/B (0/1; unused in chain), `false_leaf` chooses a background component index0…((32−k)/4−1), mapping to its root slot `k+4*index`; and `distractor_approval` takes that distractor's pool-slot integer as its sole extra argument and draws `randrange(2)` (0=false,1=true). The other non-ID namespaces have no extra arguments. False-target selection does not condition on its approval. These choices and IDs exclude topology/label/condition/budget from their keys. No key, stream or draw is selected according to results. Each of the 32 IDs is thus derived from family/k/private slot under an opaque private namespace. All IDs have the same 32-lowercase-hex format; collision is a run failure, never silently resampled. This prevents visible IDs from containing or directly exposing enumerated generator positions. The key is synthetic reproducibility material, not an API credential or edge authenticator. Reproduction uses the same frozen key. A clone without it can generate a new cohort but cannot claim byte-identical reproduction of the saved run.

No family seed, split, key, private position, topology, k, label or mutation name is passed to a selector/checker. All condition names and ground-truth fields are added to the result by the harness only after execution. Python object boundaries remain logical API separation, not protection from hostile code with access to the host/filesystem. Tests must inspect actual serialized inputs and parameter objects, not merely rely on field names in documentation.

Three conditions, with identical records and labels across their views:

1. **intact**: every asserted parent equals the private true parent.
2. **one_anchor_reference_null**: replace exactly one anchor parent slot with JSON null. Chain has one slot; fork/join chooses one of two slots uniformly from a private stream. Preserve arity and list length; the null is explicitly unresolved, not an absent optional dependency.
3. **one_anchor_reference_false_leaf**: replace that same chosen anchor slot with one uniformly chosen distractor **component root** ID. It names an existing visible record with arity0; its independently sampled approval may be true or false. Use the same distractor ID in both topologies. Preserve the other slot, approvals, arity, true DAG and R.

The affected fork branch and false target are paired across null/false views and across label/budget views. Parent arrays are canonicalized by non-null opaque ID, with null last; array order cannot reveal private A/B identities. The replacement slot is selected using private branch identity **before** this serialization; the selector sees only the final array. All nonanchor observed payloads are unchanged from their topology's intact view. No probabilistic edge-drop rate, simultaneous multi-fault view, forged approval, arity rewrite or adaptive attacker is part of the evaluation.

There is exactly one altered edge assertion in each damaged view, not an equal corruption probability per edge: fork/join has k edges versus chain's k−1. Cutting a chain anchor can disconnect k−1 true ancestors; cutting one fork/join branch disconnects m branch-interior records while the root remains reachable by the other branch. This difference is part of the **specified anchor-fault/topology intervention**, not robustness to arbitrary equally severe cuts. Do not claim a fault-location-independent benefit. Fixtures additionally exercise malformed/out-of-catalog/cyclic/duplicate assertions, but they are contract tests, not extra evaluated conditions.

## 5. Exactly two budgeted methods

Earlier SWARM-007/009/016/017 selectors, checkers and contracts remain byte-identical. New methods live in a separate namespace and do not silently generalize the old four-read implementation. Neither method receives private truth or uses approvals/label-like fields to rank records. They receive the identical catalog/query and a budgeted payload-reader capability.

### 5.1 Blind ID batch

Select the anchor first, scan every nonanchor catalog entry, sort its opaque IDs ascending, append the first B−1, and read all B distinct records in one batch. It does not parse payloads during selection. Uniform opaque ID assignment makes this a blind subset baseline conditional on the known anchor; it is deterministic given the public IDs. It is named `blind_id_batch`, not a learned or metadata-relevance baseline. The same ID order is used across every paired topology/condition/label view. This creates an exact topology negative control without using hidden truth.

### 5.2 General breadth-first pointer frontier

`pointer_frontier_bfs` uses the following same procedure for chains and arbitrary asserted branching; it has no k/topology-specific stopping rule:

1. Build an ID→catalog-entry membership/size index from all N entries. Read the anchor as the first successful one-record batch (depth 0). Maintain `read_ids`, a discovered-ID set initially containing the anchor, and a map of pending IDs to their first discovered depth.
2. After each successful **frontier** batch, process its payloads in ascending opaque ID order, even if that batch exhausts B. Decode each once. Require matching ID, integer arity in {0,1,2} (not Boolean), a list of exactly that length, and Boolean approval for wire validity. A malformed payload records a parse/shape error and yields no expansion; approval **value** never affects expansion. Evaluation generation must not create such malformed payloads; fixture failures are expected negative tests, not run exclusions.
3. For every parent slot, count a slot inspection. Null or non-32-hex syntax produces an invalid-reference diagnostic and no enqueue. For every syntactically valid ID, charge one catalog lookup, including repeated references. Ignore nonpublic IDs with an explicit counter. A visible ID already discovered/read is counted as deduplicated, with no new payload request. Otherwise mark discovered immediately and enqueue at source depth+1. Do not test private membership, approval value, expected root, true arity, or global reachability.
4. If reads equal B, stop. Otherwise choose the minimum pending depth, sort that whole depth's pending IDs ascending, and read up to the remaining budget in one batch. Remove only requested IDs. Do not mix higher depths into that batch, reorder by evidence relevance, or use unseen payloads. Process the returned payloads as in step 2. First discovery in this level-synchronous BFS is shortest asserted distance; shared parents discovered from two branches are read once.
5. When no pending IDs remain and budget remains, scan the entire catalog, collect all unread IDs, sort ascending, and read the first `B−reads` in **one final fallback batch**. Do not expand or selection-parse these fallback payloads. This fixed fallback can recover disconnected true records by chance, but cannot use private truth to choose them. Then stop.

Thus both selectors read exactly B distinct records in all valid evaluation views (N≥B). A false visible pointer is traversed as an ordinary assertion; it is not recognized as false by the selector. Cycles terminate through deduplication. If B truncates a frontier, record the pending/unread frontier and budget-exhaustion reason. If the frontier closes, record frontier-exhaustion plus any final fallback, separately from budget exhaustion. There is no early stop upon an approval value or presumed complete true set.

## 6. Checker-conditional diagnostics, not identification

The observed checker receives only the anchor ID and the **already read payload dictionary S**. It receives no catalog payload access, private DAG/R/label, k/topology, mutation name, seed or ID key. It constructs an observed ancestor closure by following asserted parents from the anchor. Validate ID/arity/list/Boolean shape, reject duplicate parents within one node, and require every dependency slot to be non-null, well-formed, present in S and acyclic. A shared ancestor reached by distinct paths is legal and memoized; a recursion-stack repeat is a cycle. Multiple asserted arity-0 terminals are legal for this general AND evaluator; requiring exactly one root or exactly k records would introduce an additional oracle/structural assumption and is forbidden.

If any reachable dependency is unresolved or malformed, output **unknown**, even if an already observed node has `approved=false`. Only after the whole asserted reachable closure is resolved, AND every unique reachable node's approval once: all true yields **asserted_normal**, otherwise **asserted_violation**. Extra read records outside that observed closure do not participate. Resolve all branches before deciding; no Boolean shortcut hides missing evidence. Report the resolved observed ID set when it exists; otherwise it is undefined, not a guessed true set.

Offline scoring separately compares with the private ledger. The outputs are claims about the resolved **asserted** graph. A false leaf can shorten/redirect that graph and yield an asserted normal outcome while the true label is violation; a negative distractor can also produce asserted violation when the true required set is normal. Even reading all true records does not force the observed checker to consult them. An apparent agreement can happen by coincidence under incomplete or false evidence. Never call agreement, recall, complete recovery, or oracle-assisted performance a genuine identification rate, verified decision, or safety rate.

Two explicitly separated diagnostics:

- **true_set_oracle** gets R privately, chooses anchor then ascending IDs in R until `min(B,k)`, with no distractor filling. It runs the same observed checker on those payloads. It is an oracle upper-bound/abstention diagnostic, not a feasible method or budget-matched competitor. Charge its actual reads and extra private input: number of truth IDs and exact canonical JSON bytes of the truth-ID list. Do not include it in method rankings/contrasts or ordinary input-cost averages.
- **full_catalog_checker** reads all N payloads in one batch and runs the same observed checker. It uses no private set for selection but exceeds B; execute/report once per family/topology/k/condition/label, without duplicating it across budgets. Charge N reads and all bytes. It shows the limit of the asserted-graph diagnostic with full observable data, not a new trusted answer. Neither diagnostic is allowed to repair assertions.

## 7. Metrics, full costs and time boundary

For each actual selected unique set S, offline truth metrics are: `complete = 1[R⊆S]`, `recall = |R∩S|/k`, `precision = |R∩S|/|S|` (0 for empty S), `distractor_reads=|S−R|`, `unread_required=k−|R∩S|`, and true-edge endpoint coverage `|{(u,v) in E_R: u,v in S}|/|E_R|`. Endpoint coverage does not authenticate observed edges and has a topology-dependent denominator. Empty S has zero completeness/recall/precision/edge coverage; checker is unknown.

Separately record observed closure resolved, checker output, offline agreement with the private label, false normal (`true violation, asserted_normal`), false violation (`true normal, asserted_violation`), unknown, and whether a resolved observed set equals R. Report denominators for label-conditioned diagnostics. False normal and false violation are both possible under false-reference redirection despite unchanged approval values. Intact resolved closure agrees with the true label by construction; that is a contract consequence, not general safety. For unresolved closure, set-equality diagnostic is null/undefined, never counted as an observed correct set. Every result retains separate fields for retrieval, checker and private label.

Account by actual invocation, without hidden amortization or cross-method derived-index reuse:

| Component | Required recorded work / bytes |
| --- | --- |
| Generator and observation preprocessing | Private node/edge allocations, observations built, canonical ID/catalog/parent sorting input counts, serialized records/bytes and elapsed time. Outside selector timing, disclosed separately; no truth-derived index supplied to methods. |
| Full catalog and query | N records ×128 =4,096 bytes plus128-byte query, charged once per method invocation. One modeled metadata/query access round. Catalog validation scans N entries; count them. No free global payload or edge access. |
| Reader backend | N store-index insertions per invocation, preparation time separately; each requested ID lookup and returned payload byte counted. This hidden storage index is not a selector feature. |
| Selector index/scan/ranking | Every own catalog-index insertion, catalog entry inspected, ID membership query, frontier insertion/removal and deduplication, payload decoded, slot inspected, sort call, sort input item and key evaluation. Counts are logical work, not hardware instruction counts. Expose repeated scans/sorts, including fallback and final truncated frontier. |

Track requested IDs, rejected/repeated requests, successful batches/rounds, reads per batch, cache reuse and pending frontier. Union/set construction is never a single read of many records. |
| Checker | Own S-index creation, cached payload parses, reachable-node and dependency-slot checks, membership lookups, recursion/visited bookkeeping, and separate elapsed time. It has no additional storage reads. Bytes already read are not retransmitted. |

Reader API rejects an entire empty/duplicate/already-read/nonpublic/over-budget batch before returning payloads. Record rejected requests and zero successful reads/bytes for that rejected batch. A successful call is one payload round regardless of batch size, with one read/512 bytes per returned ID. Evaluation rejection is an implementation failure and stops the run, not a recoverable way to sample around the budget. Expected rejection fixtures are distinct tests. Reference deduplication before requests creates no new payload read/round, but its work is counted.

Ordinary selector transmitted totals are `4096+128+512B`: **6,272 / 8,320 / 10,368 bytes** for B4/8/12. Full-catalog diagnostic is **20,608 bytes** before any separate offline truth work. Local selector-plus-reader timing excludes generator/projection and backend initialization; log those separately. Selection must not time offline scoring or its truth lookup as method work. Report checker time separately. Repeated serialization and any rebuilding within selection remain charged. Timing summaries are nondeterministic and separate from deterministic aggregates. Modeled waits at RTT0/1/10ms report both `payload_rounds×RTT` and `(1+payload_rounds)×RTT` including the one catalog/query round; idealized batch parallelism is an assumption, not measured network latency. This new total-round convention does not change old studies.

Add paired fixtures with negative distractors under a normal target label and nonzero-arity distractors, so neither a false approval nor an arity1/2 payload acts as a direct private-membership flag.

## 10. Independent audit, freezing and correction policy

### Analytic checks, not measured results

The structure and single anchor fault make several recovery probabilities calculable in advance. Preserve these checks to avoid presenting a mechanically expected pattern as a new general discovery. For a blind subset, completeness probability under uniform opaque IDs is `C(B−1,k−1)/C(31,k−1)` for B≥k and zero otherwise, independent of topology/condition/label. For a frontier with B≥k, its entire asserted reachable component fits before fallback. Let q be the number of reachable true records and d the number of reachable distractors: intact `(q,d)=(k,0)`; chain null `(1,0)`; chain false `(1,1)`; fork null `(k−m,0)`; fork false `(k−m,1)`. It reads r=q+d before fallback, leaving F=B−r slots and k−q missing true records among N−r unread candidates. Completeness probability is `C(F,k−q)/C(N−r,k−q)`, with zero when F<k−q and one when k−q=0. For B<k completeness is zero regardless of frontier order. All combinatorial quantities describe the ideal random-ID assignment distribution; they are not observed rates or additional independent samples.

In particular, a false leaf consumes an extra read, so at B=k complete recovery must be zero for the frontier in both topologies even with every other reachable true record found. The null-reference checker remains unknown even when fallback recovers R. Table/receipt arithmetic will verify these fixed predictions before implementation. Later report empirical means beside the analytic expectations; finite-sample disagreement is not grounds to discard/rerun a cohort. Per-view impossibilities (B<k completeness, label-dependent selection, topology-dependent blind recovery) remain implementation gates. The study primarily documents these access/cut/round mechanisms and their checker limitations, not algorithmic novelty.

New namespace only, suggested `src/record_topology/`, new tests and run folders. The actual implementation must keep generator/observation, capability-based selection, observed checker, offline scoring and analysis separate. Before evaluation, freeze code/config/test/fixtures/protocol/analysis plus private key provenance and bootstrap matrix. Manifests record exact UTC/KST timestamps, commands, Python/environment, source commit and hashes, initial report preservation, per-view inputs/read traces/costs and statuses. Preserve every failed run/directory/log; never overwrite an execution lock or run.

The independent auditor must **not import production generator, selector, checker, scorer or summarizer**. From saved private DAG/approvals and observations, independently recompute R/labels, k/N matching, exact allowed mutation, selector order using separately written reference logic, observed closure/verdict, all metrics, bytes/budgets/rounds/work counters, and all72 family contrasts/intervals using the saved matrix. Validate the full matrix dimensions/index range and recompute its specified generation. Assert no missing/duplicate family/view/method rows and reproduce all deterministic outputs. This is independent calculation code by the drafting agent, not independent human review or external replication.

Technical pre-evaluation corrections are allowed **only within accepted phase2**, without changing this scientific contract: syntax/import errors, serialization bugs, incorrect implementation of a frozen fixture/algorithm, or accounting instrumentation errors. Log each defect, failing evidence, exact fix and subsequent validation. Do not weaken a test, change an expected fixture, ignore a mismatch, or relabel a scientific issue as technical. Unit-test iterations are allowed within the4–6-hour gate; development-run attempts are capped at **two total** (one original plus at most one corrected attempt). A development run or independent audit failure pauses progression; an unambiguous technical fix may use that one remaining development attempt. A second failure, a scientific ambiguity or an unresolved audit mismatch is no-go. No evaluation starts until every acceptance gate is satisfied.

Scientific blockers include undefined/changed required membership, unmatched k/N/bytes, hidden truth/identity leakage, ambiguous AND/unknown semantics, uncharged global access, acceptance of a false reference as ground truth, unbounded retry/selection, an independent-audit disagreement without a demonstrated implementation error, or inability to finish validation/report within the time gate. Contract changes to topology, k meaning, labels, fault distribution/placement, observability/authentication, selectors/fallback, budgets/cost definitions, N/seeds, metrics/analysis or failure policy require a **new protocol version**, explicit research-scope coordination and a separately frozen seed range. Do not edit v1 into agreement with observed results.

After final evaluation lock, **one evaluation and one identical-setting reproduction only**. Any execution, schema, metric, cost, non-leakage, audit or reproduction failure stops that phase; preserve the partial/failed run and current report and report the exact failure. No automatic correction/retry of evaluation. If any evaluation view/aggregate has been inspected, its whole cohort is spent for method/design correction; a later expressly coordinated version requires fresh untouched seeds and preserves the failed cohort, never reclassifies it as a successful holdout. No exclusions, substitutions or result-dependent stopping. Infrastructure-only interruptions also require coordination before any retry; never infer that partial generation/inspection did not occur.

Expected nulls, worse outcomes, or a diagnostic's wrong assertion under the documented untrusted-edge contract are **results**, not scientific blockers. Preserve them. An outcome that violates a proved fixture invariant is a blocker, not a negative scientific finding. An identical-setting reproduction adds no independent families. Compare deterministic config, private ledger/labels, observed payloads, per-view results/traces/costs, bootstrap indices and aggregate summary byte-for-byte.
