## Fixed question and sample

How do cross-workflow object-ID collisions and partial retention of a shared object linkage change the fixed object-first mixture's completion relative to relation graph/join? Does its fallback prevent harm when some or all object links disappear? Both gains and losses are outcomes. Partial retention is not assumed harmful: suppressing misleading matches could help under collisions.

No new selector or checker is introduced. 12 fixed conditions yield 24 views per family, 2,304 evaluation views and 23,040 rows. ## Object projection and matched conditions

Cross **reference visibility {explicit true references, implicit/no references} × object namespace {unique workflow token, four shared buckets} × per-record retention {1, 0.5, 0}**. Pointers are exact, resources unchanged, and no false references are added. The public catalog contains every pre-cutoff record, as before.

The old generator's binary object IDs are replaced in this stage's public projection. Each workflow is assigned an opaque, deterministic token from a domain-separated SHA-256 function of seed/background/workflow ID. In the unique arm each workflow has a distinct token. In the collision arm workflows are independently mapped into four buckets by another domain-separated hash, and the bucket token is shared by all workflows assigned that bucket. Bucket assignment is fixed across retention levels and reference conditions; it is not selected from the query/truth/approval or from observed performance. Tokens use 128 hash bits with no readable phase, identity or condition flag; accidental hash collisions are checked separately from intended bucket equality.

Each record retains its shared token if its independent, condition-invariant hash uniform is below p. Otherwise its object field gets an opaque per-event token, identical across arms, which cannot serve as a shared-object link. This operationalizes **missing linkage**, not a missing record or a blank/null field. It avoids treating all missing IDs as one shared object. Partial retention means p=0.5 applied to every record, including the anchor, not a guaranteed half of the true chain. Masks are nested for p=0/0.5/1 and independent of reference visibility and truth. The observer may use private workflow IDs to generate this synthetic signal; selectors receive only the resulting public metadata and their payload reader, never workflow IDs, masks, bucket assignments or truth.

Collisions create possible distractors only when another workflow's earlier visible record has the anchor's retained token. Measure realized candidate ambiguity and selected distractors rather than equating bucket assignment with realized damage. Ground truth continues to be the private actual-parent chain, independent of object IDs. No record, payload, true edge, approval or query is changed by an object condition; reference projection alone changes reference metadata. Background settings are separately generated, not causal load interventions.

## Fixed outcomes and contrasts

Primary metric: complete true-record retrieval. Primary contrasts: mix minus graph for each of the 12 conditions, pooling the two backgrounds with equal weight **within each family**; report both backgrounds separately too. Condition-level mean differences, all method completion/correct/unknown counts and descriptive 95% intervals are retained. Overall equal-grid differences are secondary, not population prevalence estimates.

Prespecified sensitivity contrasts within each reference regime: collision p=1 minus unique p=1; unique p=0.5 minus unique p=1; collision p=0.5 minus collision p=1; unique p=0 minus unique p=1; collision p=0 minus unique p=0 (negative control). Retain these for all methods' completeness and correct verdicts. No condition is selected for the main report based on outcome. Main table shows all 12 conditions; the companion aggregate carries all method/background contrasts and diagnostics.

Use 2,000 paired family bootstrap resamples with percentile order statistics 49/1949, as in stage 1. Per-background contrasts have one difference per family. Pooled-condition differences average the two background differences before resampling. Report degenerate intervals and all outcomes, without multiplicity correction, causal population inference or claims of general robustness. Code/data availability and CI limits remain explicit.

Diagnostics: retained true matches, anchor retention, same-ID cross-workflow candidates, mix-selected distractors and fallback frequency; exact-pointer success, graph/join identity, correct/unknown/wrong verdicts, per-method read traces and costs. p=0 should reproduce mixture=join selection because the object pass finds no shared matches. Unique-token partial retention should not be presumed worse: preselected matches are true predecessors and join fills the budget. Under collisions those slots can instead be occupied by distractors. Explicit-reference graph and exact-pointer retrieval should stay complete in this restricted model. Fixture tests verify these mechanisms without changing methods to handle the stress.
