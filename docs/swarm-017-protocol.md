# Fixed relation reservation protocol

**Public snapshot adaptation.** This describes the historical study; it is not a new preregistration or an execution instruction. Private Git ancestry, original locks and raw evidence are absent. Source commit/file hashes in [provenance](../provenance.json) identify the supplied bytes but do not independently establish when the design was fixed. See [evidence limits](evidence-availability.md). Operational coordination text is omitted; the original remains preserved privately.

This follow-up was designed after the object-linkage stress results. It fixes one two-slot reservation rule; its gains and regressions are both retained. Earlier evaluation cohorts are not pooled into this study.

## Fixed selector and accounting

Add only `relation_reserved_mix`, keeping all nine existing methods and the true-record diagnostic. The new method receives the same public metadata/catalog and anchor, without ledger, workflow IDs, truth, or payload-dependent choice.

1. Execute the existing `relation_join` metadata selector to its normal four-record budget, including its normal recency fallback. This produces the anchor and three ranked nonanchor IDs. Execute all join work even when object matches would suffice; do not stop join at two neighbors.
2. Reserve the anchor and join's first two nonanchor records in their existing order. The join weights, heap order (distance, negative timestamp, event ID), and fallback order remain unchanged.
3. Scan every nonanchor public record. Eligible object candidates share the anchor's object token and have strictly earlier timestamps; exclude already reserved IDs. Sort eligible candidates by decreasing timestamp then increasing event ID. Append the first candidate if any; otherwise append the first unused ID in the already computed join ranking. Exactly four distinct public IDs including the anchor must result.
4. Only then read the four payloads in one batch. Never use a fifth read, inspect a payload to change selection, or query hidden labels. The shared checker and scoring remain unchanged.

Charge the full existing join's work plus a second N-record metadata index, N−1 object-candidate checks, and sorting all eligible unreserved candidates. Charge all join edge visits, fallback sorting and checks; relation fallback reuses the stored rank rather than reexecuting join. Catalog transmission is charged once, plus the anchor query and four 512-byte payloads. Backend initialization/index and four payload lookups are reported separately as before. Metadata serialization may occur twice in local implementation and remains included in measured local time; these are not additional transmitted inputs. Measured selector-plus-read time is local Python time; projection generation and backend initialization are outside its timing boundary. Equal four-read budgets do not imply equal computation, information, or latency.

## Development, execution and stop rules

Use deterministic hand fixtures for both improvement and regression, duplicate object matches, absent/exhausted candidates and join fallback, timestamp/ID ties, four unique reads in one batch, payload/label independence and complete cost accounting. Development invariants use only seeds 501–506. Run the unit/full related suite, then one development run and independent saved-artifact audit using a development snapshot. After those pass, freeze the final source/config/tests and protocol snapshot; run evaluation once, then one identical-setting reproduction. Reproduction adds no independent units. Independently reconstruct the new ranking and its computation costs without importing production selectors/generator/scorer/summary, and audit original projection, ground truth, metrics, trace/budget and every interval.

Any experiment execution or validation error stops evaluation work: preserve failure details and completed scope, report the exact issue, and do not automatically repair/retry to rescue results. No incomplete audit is called complete. Do not inspect evaluation seeds before the final lock, alter code/config/N after seeing outcomes, exclude families, or start another experiment. Technical development defects before evaluation are also disclosed; if a development run or its audit fails, stop and report instead of proceeding to evaluation. No outcome-dependent continuation.
